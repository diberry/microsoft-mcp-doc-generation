## Root Cause



Pipeline design is **determinism first, AI second** (ARCHITECTURE.md). Step 1 extracts all parameter names and required status from CLI metadata. Step 2 passes this to the LLM, but the output is not deterministically verified and repaired before validation.



The required parameter names are **known facts** from Step 1 — we should not rely on AI compliance.



## Proposed Fix



**Deterministic prompt repair pass** in Step 2, between AI generation and validation:



1. **New class**: `DeterministicPromptRepairer` in `DocGeneration.Steps.ExamplePrompts.Generation`

2. **Input**: Generated prompts + required parameter list from cli-output.json (Step 1)

3. **Logic**: Run `ParameterCoverageChecker.GetConcretePromptCoverage()` on each prompt. For any uncovered required param, inject `{natural-name} '{example-value}'` into the prompt text.

4. **Call site**: `ExamplePromptsStep.cs`, after AI generation, before validation

5. **Guarantee**: Uses the **same** `ParameterCoverageChecker` the validator uses — repaired prompts guaranteed to pass validation



### Why this works

- `ParameterCoverageChecker` converts param names to slug variants (e.g., `resource-group` → "resource group", "resource-group", "resource_group")

- It strips suffix words ("name", "text", "array") → also matches just the base word

- The repair injects text that satisfies the exact same checker the validator calls

- No prompt engineering needed — deterministic post-processing



## Validation Plan



### Unit tests MUST prove correctness without running the pipeline



The `DeterministicPromptRepairer` is deterministic — it takes prompt text + required params → outputs repaired text. All 80 failure patterns can be validated with unit tests.



**Test fixture strategy**: Build test cases from real failure data (below). Each test:

1. Constructs a prompt string that mimics what AI generated (missing the param name)

2. Passes it through `DeterministicPromptRepairer` with the required params

3. Asserts `ParameterCoverageChecker.GetConcretePromptCoverage()` returns full coverage



**Required test categories** (from actual failures):



| Category | Example param | Count | Test verifies |

|----------|--------------|-------|---------------|
