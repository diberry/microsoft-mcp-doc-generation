# DocGeneration.Baseline.Beta34.Tests

Deterministic xUnit guard suite that **freezes the Azure MCP `3.0.0-beta.34` catalog
critical-failure baseline** (issue #813, Step 1). It pins the 34 logical critical-failure
records captured from run `generated-20260813T162453` as immutable, sanitized fixtures plus a
provenance-stamped manifest, and asserts an exact, revert-proof classification for every record.

> **These tests do not fix any A/B/C/D defect.** They only prove the frozen baseline is complete,
> secret-free, deterministic, and classified exactly once. Defect fixes are later steps.

## Purpose

- Prove the 34 sanitized fixtures are byte-for-byte immutable (`sanitizedSha256`) and faithful to
  the original capture (`sourceSha256`).
- Pin the classification (`root` / `cascade` / `mixed` / `diagnostic`) and error-class taxonomy
  (`A` / `B` / `A+B` / `C`) counts exactly.
- Reconcile the Class-D dependency accounting (`hasUpstreamStep2` / `upstreamStableIds` = 10 dependent
  records, 16 links) and the chain-role taxonomy (`chainRole` root 24 / cascade 10) **independently**
  of the classification (`root`/`cascade`/`mixed`/`diagnostic`) counts.
- Recompute every number in the manifest `accounting` block from the records + inventory and pin it.
- Enforce that no secret, PII, machine/user name, temp GUID path, or absolute repo/home path
  survives sanitization (across fixtures, manifest, AND `source-inventory.json`), and that only the
  approved placeholder tokens remain.

## Frozen inputs (produced by Quinn's generator, **not** by this project)

| Path | Contents |
|------|----------|
| `Fixtures/critical-failures/*.json` | 34 sanitized catalog records (namespace prefix retained) |
| `Fixtures/beta34-baseline-manifest.json` | schema-versioned manifest: `provenance` + `accounting` + 34 `records[]` |
| `Fixtures/source-inventory.json` | committed capture inventory: 68 physical copies (34 catalog + 34 namespace) with per-copy `sha256`, `logicalIdentity`, `stableId` — lets the immutability / duplicate-accounting tests run on a **clean checkout** without the gitignored source run |

The manifest schema (per AD-028) is:

```
{ schemaVersion, provenance{ repoCommitSha, sourceRunDir, azureMcpBuild, sanitizerVersion, ai{ source, model,
    apiVersion, temperature, seed, step2ExamplePrompts{…}, step4ToolFamilyCleanup{…} }, configHashes, promptHashes,
    captureTimestampUtc, toolVersions },
  accounting{ logicalRecords, physicalCopies, step2Records, step4Records, dependentRecords, dependencyLinks,
    chainRoleCounts{root,cascade}, classificationCounts{root,cascade,mixed,diagnostic}, errorClassCounts{A,B,AB,C} },
  records[]{ stableId, namespace, stepId, artifactName, recordedAtUtc, sourceRelativePath, sourceSha256,
    sanitizedRelativePath, sanitizedSha256, classification, errorClass, errorClasses[], hasUpstreamStep2, chainRole,
    upstreamStableIds[], physicalCopies[], rationale } }
```

`provenance.ai` is derived from the run's sanitized **run logs** (`source: "run-log"`), NOT from
`mcp-tools/sample.env`: model `gpt-5-mini`, apiVersion `2025-03-01-preview`, `temperature`/`seed` `null`.

Stable ID scheme: `{namespace}.{stepId:D2}.{artifactSlug}.{ordinal:D2}` (e.g. `storage.02.account-create.01`).

## Classification input

`scripts/baseline/beta34-classification.json` (repo root) is the mechanically-derived classification
keyed by source filename, generated by `scripts/baseline/classify_beta34.py`. Quinn's generator
consumes it to populate the manifest `classification` / `errorClass` / `hasUpstreamStep2` / `rationale`
fields.

## Path resolution

Fixtures and the source run are resolved from the **repo root** (the directory containing
`mcp-doc-generation.sln`), discovered by walking up from `AppContext.BaseDirectory`. This is robust
on Windows and Linux and does not depend on copy-to-output.

### Approved placeholder tokens (T22)

The sanitizer allowlist is the **eight** tokens defined by
`scripts/baseline/New-Beta34Baseline.ps1` and documented in `scripts/baseline/README.md`:
`<REPO>`, `<TEMP>`, `<USER>`, `<USER_HOME>`, `<HOST>`, `<RUNSTAMP>`, `<GUID>`, `<PATH>`.
`BaselineContext.ApprovedPlaceholders` mirrors this exact set.

### Sanitizer idempotence

Sanitizer determinism / idempotence (a 2nd pass is byte-identical) is proven by
`scripts/baseline/New-Beta34Baseline.ps1 -VerifyOnly` — evidence in
`scripts/baseline/evidence/verify-run.txt` — **not** by a C# test. T22 only guards the
*output shape* (approved placeholders only, no residual absolute paths).

## Running

```bash
dotnet build mcp-tools/DocGeneration.Baseline.Beta34.Tests/DocGeneration.Baseline.Beta34.Tests.csproj --configuration Release
dotnet test  mcp-tools/DocGeneration.Baseline.Beta34.Tests/DocGeneration.Baseline.Beta34.Tests.csproj --configuration Release
```

All 32 tests are registered in `mcp-doc-generation.sln`, so they also run in CI via
`dotnet test mcp-doc-generation.sln` (`build-and-test.yml`). On a clean checkout / CI the suite is
GREEN (31 passed, 1 skipped) — no gitignored source run is required.

### Opt-in deep source-run verification (`BETA34_VERIFY_SOURCE_RUN`)

`T4b_DeepVerify_LiveSourceRun_Hashes_Match_Inventory` is an **additive** deep check that hashes the
live (gitignored) source run `generated-20260813T162453/` and matches every byte against
`source-inventory.json`. It cannot run on CI, so it is an **explicit opt-in**:

```bash
# Windows PowerShell
$env:BETA34_VERIFY_SOURCE_RUN = "1"; dotnet test ... --filter FullyQualifiedName~T4b_DeepVerify
# bash
BETA34_VERIFY_SOURCE_RUN=1 dotnet test ... --filter FullyQualifiedName~T4b_DeepVerify
```

Without the opt-in it reports as a **visible skip** (via `[SkippableFact]`) with a clear reason —
never a silent pass. When opted in, a missing source run or any hash mismatch **fails** the test.

### RED / GREEN evidence

- `evidence/red-run-remediation.txt` — RED via `BETA34_FIXTURES_DIR` pointed at a **tampered** copy
  (mutated to wrong values) so each pinned assertion fails on a real `Assert` mismatch, plus an
  absent-input run proving non-vacuity.
- `evidence/green-run-remediation.txt` — full GREEN + the opt-in deep-verify pass.

The `BETA34_FIXTURES_DIR` override repoints the frozen-input root (fixtures + manifest + inventory)
so RED-first evidence can be reproduced without disturbing the committed working tree; it is not
used by CI.
