  Cameron's row M6 names TWO guards (T9 and T13). Under the M6 mutation (execute
  suppressed dependents normally instead of suppressing them):
    * T9 went RED (Step 3 Executions 0 -> 1) — the behavior IS guarded, so M6 is PROVEN.
    * T13 stayed GREEN. Root cause: the test's RecordingNamespaceStep dependents default
      to a DryRun SUCCESS outcome, so when M6 lets them execute they complete successfully
      and emit NO step-03/step-04 "critical" JSON. T13 asserts on the presence of that
      critical JSON, which is absent whether the step is suppressed OR succeeds — so T13
      cannot distinguish the mutation.
  Impact: LOW. M6's production change is fully guarded by T9; the revert proof holds. The
  (M6,T13) coupling is simply redundant/non-discriminating for this mutation. To make T13
  independently discriminate M6, its dependents would need to be seeded with a failing/critical
  outcome so that "executed vs suppressed" changes the emitted JSON. Recorded honestly; no
  production or test code was altered to force it.

  NOTE ON COLLATERAL RED (M23, M26, M32, M33): several rows produce additional RED tests
  beyond the single named test. This is expected and truthful — e.g. M26's case-insensitive
